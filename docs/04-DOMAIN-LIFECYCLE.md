# Event Booking API — Domain Lifecycle

## 1. Overview

The main application domains have different states during the booking process.

This document presents the lifecycle of:

- Event
- EventSeat
- Booking
- Payment
- Waitlist
- Notification

---

## 2. Event Lifecycle

An event moves through different states during its lifecycle.

```mermaid
stateDiagram-v2
    [*] --> DRAFT

    DRAFT --> PUBLISHED
    PUBLISHED --> COMPLETED
    PUBLISHED --> CANCELLED

    DRAFT --> CANCELLED

    COMPLETED --> [*]
    CANCELLED --> [*]
```

### Flow

`DRAFT` → event is created but not active.

`PUBLISHED` → event is available to users.

`COMPLETED` → event has finished.

`CANCELLED` → event has been cancelled.

---

## 3. EventSeat Lifecycle

`EventSeat` represents the status of a seat for a specific event.

```mermaid
stateDiagram-v2
    [*] --> AVAILABLE

    AVAILABLE --> RESERVED
    RESERVED --> SOLD

    RESERVED --> AVAILABLE

    SOLD --> [*]
```

### Flow

- `AVAILABLE` — seat can be selected.
- `RESERVED` — seat belongs to an active booking.
- `SOLD` — booking/payment process has been completed.
- A cancelled reservation can return the seat to `AVAILABLE`.

---

## 4. Booking Lifecycle

A booking starts when a user successfully reserves one or more event seats.

```mermaid
stateDiagram-v2
    [*] --> PENDING

    PENDING --> CONFIRMED
    PENDING --> CANCELLED

    CONFIRMED --> COMPLETED
    CONFIRMED --> CANCELLED

    COMPLETED --> [*]
    CANCELLED --> [*]
```

### Main Flow

```mermaid
flowchart LR
    A[Create Booking]
    --> B[PENDING]
    --> C[CONFIRMED]
    --> D[COMPLETED]
```

Alternative flow:

```mermaid
flowchart LR
    A[PENDING / CONFIRMED]
    --> B[CANCELLED]
```

---

## 5. Payment Lifecycle

A payment is connected to a booking.

```mermaid
stateDiagram-v2
    [*] --> PENDING

    PENDING --> COMPLETED
    PENDING --> REFUNDED

    COMPLETED --> REFUNDED

    REFUNDED --> [*]
```

### Main Flow

```mermaid
flowchart LR
    A[Create Payment]
    --> B[PENDING]
    --> C[COMPLETED]
```

If a refund is required:

```mermaid
flowchart LR
    A[COMPLETED]
    --> B[REFUNDED]
```

---

## 6. Waitlist Lifecycle

When booking is not possible, the user can join the event waitlist.

```mermaid
stateDiagram-v2
    [*] --> WAITING

    WAITING --> NOTIFIED
    WAITING --> CANCELLED

    NOTIFIED --> CONVERTED
    NOTIFIED --> CANCELLED

    CONVERTED --> [*]
    CANCELLED --> [*]
```

### Main Flow

```mermaid
flowchart LR
    A[Join Waitlist]
    --> B[WAITING]
    --> C[NOTIFIED]
    --> D[CONVERTED]
    --> E[Booking]
```

This creates a direct connection between the waitlist and booking process.

---

## 7. Notification Lifecycle

Notifications inform users about important system operations.

```mermaid
stateDiagram-v2
    [*] --> UNREAD

    UNREAD --> READ

    READ --> [*]
```

Notifications can be generated by:

```mermaid
flowchart LR
    B[Booking] --> N[Notification]
    P[Payment] --> N
    W[Waitlist] --> N

    N --> U[User]
```

---

## 8. Booking + Seat + Payment Lifecycle

The most important combined lifecycle is the reservation process.

```mermaid
flowchart TD
    A[User Selects Seat]
    --> B{EventSeat AVAILABLE?}

    B -->|No| W[Waitlist]

    B -->|Yes| C[Create Booking]
    C --> D[Booking PENDING]
    D --> E[EventSeat RESERVED]

    E --> F[Payment PENDING]
    F --> G{Payment Completed?}

    G -->|Yes| H[Payment COMPLETED]
    H --> I[Booking CONFIRMED]
    I --> J[EventSeat SOLD]

    G -->|No / Cancel| K[Booking CANCELLED]
    K --> L[EventSeat AVAILABLE]
```

This flow keeps the status of the booking, payment and event seat synchronized.

---

## 9. Waitlist to Booking Lifecycle

The alternative booking path starts when seats are unavailable.

```mermaid
flowchart TD
    A[Seat Unavailable]
    --> B[Join Waitlist]
    --> C[WAITING]

    C --> D{Seat Available?}

    D -->|No| C
    D -->|Yes| E[NOTIFIED]

    E --> F[CONVERTED]
    F --> G[Create Booking]
    G --> H[Reserve EventSeat]
```

---

## 10. Lifecycle Summary

The main domain lifecycles are:

| Domain | Main Flow |
|---|---|
| **Event** | DRAFT → PUBLISHED → COMPLETED |
| **EventSeat** | AVAILABLE → RESERVED → SOLD |
| **Booking** | PENDING → CONFIRMED → COMPLETED |
| **Payment** | PENDING → COMPLETED |
| **Waitlist** | WAITING → NOTIFIED → CONVERTED |
| **Notification** | UNREAD → READ |

Alternative states such as `CANCELLED` and `REFUNDED` handle interrupted or reversed processes.

---

## Core Business Lifecycle

```mermaid
flowchart LR
    EVENT[Event]
    --> SEAT[EventSeat AVAILABLE]
    --> BOOKING[Booking PENDING]
    --> RESERVED[EventSeat RESERVED]
    --> PAYMENT[Payment]
    --> CONFIRMED[Booking CONFIRMED]
    --> SOLD[EventSeat SOLD]
```

This lifecycle represents the core business process of the Event Booking API.
